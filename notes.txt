@AuthenticationPrincipal - is a Spring Security annotation
Injects the current authenticated user to the controller
It is automatically injected in the controller parameter
auto populated in UserDetails object
UserDetails - is a built in class from Spring Security

Authentication Providers are components that handle
the verification of credentials provided by users
-Create an Authentication token

Default Authentication provider -> DaoAuthenticationProvider
DaoAuthenticationProvider implements authenticate method from extended class

InMemoryAuthenticationProvider - authenticates users by using in memory credentials and not a DB
stores and manages user credentials within application's memory, ok for small apps
AuthenticationProvider -> UserDetailsService -> Memory, not DB
-InMemoryAuthenticationProvider is used for developing and testing
-for limited users, prototypes


AuthenticationProvider interface - authenticates user
Method authenticate returns an Authentication object

UserDetails interface is a core component in spring security
that represents a user in the application
-It provides necessary information about the user sch as
username, password, and authorities

Create a costume implementation of UserDetails to require specigic details
for authentication.
In this project UserDetailsImpl implements UserDetails representing User

UserDetailsServiceImpl - Tell Spring how to load UserDetails
Loads User from UserRepository,
then converts it into our costume UserDetailsImpl

The costume UserDetailsImpl adds more attributes for a user then the default ones
The costume UserDetailsServiceImpl tells spring what repository to use
to find the details from the User that I want to use

Without these 2 classes Spring will not be able to authorize
or authenticate costume User implementations

Role based authorization is a method on restricting access
on users on what they allowed to do
Example:
Customer - Permission to access personal account
Teller - Access to customer information
Admin - Full systems access, user and role management

In-Built classes for Authorization
GrantedAuthority (interface) -> SimpleGrantedAuthority (class)
When assigning a role to a User, GrantedAuthority is
used to assign a role tp that user

METHOD LEVEL SECURITY
*To use Method Level Security, we must enable it in our configuration
by adding the annotation @EnableMethodSecurity at class level
-@PreAuthorize("hasRole('ADMIN') or hasRole('USER')"), used at method level in service classes
-@Secured({"ROLE_USER", "ROLE_ADMIN"})
-@RolesAllowed({"ROLE_USER", "ROLE_ADMIN"})
-@PostAuthorize,  evaluates authorization after evaluating method
-@PreFilter and @PostFilter
